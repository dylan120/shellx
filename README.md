# ShellX

ShellX 是面向 macOS 的 SSH 会话管理桌面应用。当前仓库已切换为 Electron/TypeScript 实现，不再包含旧 Swift/Xcode 工程。

## 当前实现范围

- Electron、TypeScript、xterm.js 和 node-pty 构建的 macOS 桌面应用。
- 左侧文件夹/会话树，支持新增、编辑、复制、删除、搜索、拖拽整理会话。
- 终端工作台支持本机 shell 标签和 SSH 标签，标签可切换、拖拽排序、复制、重连、断开和关闭。
- SSH 连接通过系统 `/usr/bin/ssh` 发起，支持主机、端口、用户名、SSH Agent、私钥文件、账号密码、启动命令和远端网络出口配置。
- SSH 会通过 OpenSSH `SendEnv` / `SetEnv` 发送 `LANG=C.UTF-8` / `LC_CTYPE=C.UTF-8`，并在交互式 shell 启动前导出同样的 locale，避免远端 shell 退回非 UTF-8 locale 后把中文输入字节误解释为 readline 控制动作。
- 账号密码可保存到 macOS Keychain，并只在远端真正提示密码时读取和自动回填。
- 会话、文件夹、脚本和设置使用 Electron 应用支持目录持久化；首次启动会尝试迁移旧 ShellX 应用支持目录中的数据。
- 脚本管理支持 Shell/Python 语法高亮；批量执行通过系统 `/usr/bin/ssh` 非交互执行脚本。
- 终端支持 xterm.js fit/resize、长行重排、`Command + ←/→` 行首/行尾、选区复制、右键菜单、状态栏和 lrzsz/SFTP 传输入口。
- 全局设置支持主题、窗口行为、终端历史行数、后台标签冻结和应用更新。
- 应用更新读取 GitHub Release，下载带 SHA256 校验的 `.dmg` 或 `.zip` 资产，下载完成后由用户点击重启安装。

## 常用命令

```bash
cd electron-shellx
npm install
npm run dev
npm run typecheck
npm run build
npm run package:dir
```

根目录脚本：

```bash
./scripts/build-electron-dmg.sh
./scripts/install-electron-macos.sh
./scripts/manual-release-electron-version.sh 1.2.0
```

`npm run dev` 会启动 Vite 和 Electron 开发环境。`npm run package:dir` 会生成 `electron-shellx/release/mac-arm64/ShellX.app`，并做 ad-hoc 签名和扩展属性清理。

## 生成 DMG
本仓库当前提供一版可直接在 Xcode 中打开的 MVP 工程，包含：

- 原生 `SwiftUI` macOS App 工程骨架
- 默认以前台 macOS 应用方式运行，会在程序坞和应用切换器中显示图标
- 工程内置最小 AppIcon 资源，默认在程序坞中显示 ShellX 图标
- 应用启动后默认打开一个本机终端标签，优先使用 `/bin/zsh` 作为本地 shell
- 应用菜单“文件”下提供“全局配置”入口，可统一管理界面主题、窗口行为、鼠标 / 触控板行为和终端历史行数上限
- 顶部菜单栏提供“脚本”入口，可管理常用脚本并批量选择会话执行
- “文件”菜单支持全量导出和导入会话、文件夹与脚本；导入前会自动备份当前数据，密码仍由系统 Keychain 管理，不写入导出文件
- 全局配置支持检查 GitHub Release 更新，可开启启动时自动后台更新，也可手动检查并显示下载进度
- 本地分文件持久化的文件夹树、SSH 会话配置和脚本库；会话按左侧结构树拓扑保存为目录/文件，脚本按单脚本文件保存，并兼容历史 `sessions.json` / `scripts.json` 自动迁移
- 会话管理窗口：左侧文件夹/会话树、详情面板、搜索、编辑
- Electron 新版左侧会话栏收起后不保留窄栏，主工作区会占满窗口宽度，并通过左上角展开按钮恢复侧栏。
- 会话管理、终端工作台、脚本管理和全局配置已统一为原生 macOS 工具型视觉风格，包含更清晰的分组面板、状态胶囊、标签样式、精简边框层级和主次操作层级
- UI 设计基线沉淀在 `ShellXUI` 和 [docs/ui-design-system.md](/home/dylan/project/shellx/docs/ui-design-system.md)，用于统一页面背景、侧栏、分组面板、状态胶囊、空态和表单层级
- 基于 `SwiftTerm` + 自管 PTY + 系统 `/usr/bin/ssh` 的内嵌终端标签页，可运行交互式 SSH 会话和常见 TUI 程序
- 终端支持增强版 `lrzsz`：远端 `rz` 时可多选本地文件上传，远端 `sz` 时可选本地目录接收，并在终端底部栏持续展示进度与速率
- 当前活跃 SSH 会话支持通过系统 `/usr/bin/sftp` 发起文件和文件夹上传/下载
- 连接前支持 ShellX 自己的 `known_hosts` 首次确认，私钥模式支持复用 macOS/OpenSSH `UseKeychain`
- 支持账号密码认证；当远端真正提示密码时，ShellX 会优先从系统 Keychain 读取并自动回填，未命中时再提示输入一次
- 支持在 SSH 会话中开启远端动态转发，让服务器侧进程通过当前 Mac 的本地网络出口访问外网服务
- 支持本地脚本库，脚本保存在应用支持目录并可通过全部会话树选择目标会话批量执行

## 关键假设

- 当前版本是本地单用户桌面应用，不涉及云同步或多人协作
- 当前版本优先支持 `SSH Agent`、私钥和账号密码认证
- 当前终端窗口基于 `SwiftTerm`，优先提供接近原生终端的交互体验

## 功能说明

### 会话管理

- 支持新建顶级文件夹和子文件夹
- 支持在左侧“全部会话”右键菜单中新建根层级会话或文件夹
- 支持在左侧文件夹菜单中直接在当前文件夹下新建会话
- 支持在左侧文件夹树中直接展开查看会话，并按文件夹树筛选会话
- 支持在左侧“全部会话”树中拖动会话或文件夹到其他文件夹；拖到“全部会话”可移回根层级
- 支持新建、编辑、复制、删除 SSH 会话
- 支持按会话名称、主机、用户名搜索

### SSH 连接

- 支持配置主机、端口、用户名、私钥文件、启动后预执行命令
- 支持为会话配置多个标签，用于环境、角色和用途标记
- 私钥认证模式下，会话编辑页通过本机文件选择窗口选取私钥文件，不需要手动填写路径
- 账号密码认证模式下，可在会话编辑页重新设置登录密码；保存时会立即新建或刷新系统 Keychain 条目，留空保存则保持现有已保存密码不变
- 连接时调用系统 `ssh` 命令，参数由会话配置拼装；首次连接和已信任主机都会以前置 `ssh-keyscan` 对比当前可用 host key 集合，发现服务器新增算法时会提示确认更新，再交给 OpenSSH 使用本地记录严格校验
- SSH 会话启动时会为本地 `ssh` 客户端补齐 UTF-8 locale，并显式发送 `LANG` / `LC_CTYPE` 到远端，尽量避免图形环境缺少 locale 时出现中文输入回显乱码、列宽计算异常或表格错位
- 会话编辑页可启用“远端网络出口”。本机网络出口模式会使用 OpenSSH 远端动态转发，在服务器侧监听一个 SOCKS5 端口，例如 `socks5h://127.0.0.1:1080`，服务器上的 `curl`、包管理器或构建工具可通过该代理走当前 Mac 的网络访问外网
- 远端网络出口也支持转发到当前 Mac 上已有的本地代理，例如把服务器侧 `127.0.0.1:18080` 转发到 Mac 的 `127.0.0.1:7890`，远端进程继续使用服务器本机代理地址即可
- 远端网络出口默认只绑定服务器本机 `127.0.0.1`；如改为 `0.0.0.0` 或 `*`，同服务器网络内其他主机也可能访问该代理入口，需要确认服务器防火墙、账号权限和使用范围
- 远端网络出口可选择连接后自动设置 `ALL_PROXY`、`HTTPS_PROXY` 和 `HTTP_PROXY`。未开启时，ShellX 只建立代理入口，用户可在远端命令中按需手动指定代理环境变量
- 终端标签页支持键盘输入、ANSI/TUI 渲染、断开连接、重连
- 当前活动终端会在标签切换、窗口重新激活、终端区域点击、标签栏点击和终端底部栏点击后主动恢复 AppKit 键盘焦点，避免光标停留在空心块非焦点态时中文输入法组合文本没有进入终端输入链路
- 终端输入会将增强键盘协议下的可打印字符和 Ctrl 组合键归一化为普通 UTF-8 或传统控制字节，并过滤焦点切换报告和方向键释放事件，避免远端 shell 将 `CSI u` 或扩展 CSI 序列回显到提示符
- lrzsz 与 SFTP 上传下载进行中按 `Ctrl+C` 会取消当前传输，并清理本地 helper / sftp 子进程
- 默认会先打开一个“本机终端”标签；你仍可继续从左侧会话树打开 SSH 标签，并在顶部标签栏间切换
- 默认打开的“本机终端”会以非 login shell 方式启动；复制出来的新本机终端标签同样使用非 login shell，避免重复加载 login 初始化逻辑
- 本机终端启动时会同步更新子进程的 `SHELL` 环境变量，使其与实际启动的 shell 一致，避免 `echo $SHELL` 与真实进程不一致
- 本机终端启动时会优先继承宿主进程已有的 `LANG` / `LC_ALL` / `LC_CTYPE`；若图形环境未提供 locale，则兜底为 UTF-8，避免 `ls` 等命令显示中文目录名乱码
- 本机交互终端会移除宿主进程继承来的 `NO_COLOR`，并保留 `TERM=xterm-256color` / `COLORTERM=truecolor`，避免 Codex CLI 等工具因环境变量禁用 ANSI 彩色输出。
- 终端子进程启动时会使用当前视图的实际列数和行数创建 PTY；拖动调整窗口大小后，也会把最新尺寸同步给 PTY，让 shell、长行输出和常见 TUI 程序按新窗口宽高重排
- Electron 新版终端会先按 xterm 实际测量结果创建 PTY，并在创建、切换标签、窗口拖拽缩放和侧栏展开/收起时实时重新 fit；可视终端按 xterm 自定义滚动条和右侧字形溢出安全区换算列数，PTY 与 xterm 使用同一列宽，避免 Codex CLI 等 TUI 按另一套宽度排版，同时通过像素安全区避免 `ps aux` 等长行输出末端压到滚动条或最右绘制边界。
- Electron 新版终端会固定 Chromium 页面缩放，避免误触页面级缩放后 xterm 字体测量、列宽和视觉密度突然变化；终端 ANSI 颜色继续交给 xterm.js 按远端控制序列原样渲染。
- Electron 新版终端支持 `Command + ←` / `Command + →` 移动到当前命令行行首 / 行尾，便于快速编辑长命令。
- 同一个 SSH 会话支持同时打开多个独立标签；每个标签都会维护自己独立的终端实例和连接状态
- 后台终端标签会保持连接并持续维护各自的终端屏幕状态；切换标签时只允许当前活动标签接收键盘输入，避免输入串到其他标签
- 后台终端标签即使不可见也会继续附着 SwiftTerm 视图并消费 PTY 输出，避免长时间切换后只回放半截 ANSI/TUI 字节造成显示错乱
- 若系统回收了隐藏终端视图且后台输出超过安全缓存上限，ShellX 会丢弃不完整的原始控制字节并给出终端内提示，避免半截 ANSI 状态污染恢复后的画面
- 顶部标签支持拖动自由排序
- 鼠标悬停在顶部终端标签上时会显示该标签对应终端的实时预览浮层，预览不拦截点击，便于不切换标签也能快速查看后台输出
- 顶部标签支持 `⌘P` 快速搜索并切换已打开终端；后台标签出现新输出时会显示未读提示，遇到错误或交互提示会使用更醒目的状态点
- 当打开终端标签达到 12 个时，顶部会显示资源管理提示条，可快速打开切换器、关闭右侧标签或只保留当前标签，降低后台终端常驻带来的内存压力
- 资源管理提示条和标签右键菜单支持冻结后台标签：冻结后会卸载后台 SwiftTerm 视图但保留 PTY 连接，输出进入有限缓冲，切回标签时自动解冻并回放
- 打开 12 个及以上终端时会按最近访问顺序自动冻结较久未使用的后台标签，并保留最近 6 个后台标签为热标签；连接中、传输中、等待确认或出现提示/错误的标签不会被自动冻结
- 设置页可调整自动冻结开关、触发阈值和热标签数量；关闭自动冻结会恢复已自动冻结的标签，但不会影响手动冻结的标签
- 标签右键菜单支持固定/取消固定；固定标签会显示 pin 标记，并跳过批量冻结和自动冻结，适合长期保留核心服务器或长任务窗口
- 终端标签操作位于顶部栏，通过右击标签菜单执行切换、复制到新标签、重连、断开、复制调试、清空调试、关闭右侧标签页、关闭其他标签页、关闭所有标签页和关闭；复制出的新标签会插入到源标签右侧
- 所有关闭终端标签的操作都会先弹出确认窗口，用户确认后才会断开连接并关闭标签页；若标签仍在传输、连接或有未读输出，确认文案会明确提示风险
- 终端内容区支持右击菜单，可执行复制当前选中文本、粘贴系统剪贴板内容、复制为命令、打开选中链接、通过 SFTP 下载选中路径和关闭当前标签页
- 粘贴多行或包含高风险片段的命令前会显示确认提示，避免误粘贴破坏性命令
- 终端内容区左侧保留少量输出留白，避免靠左拖拽复制文本时误触发侧栏宽度调整
- 终端内容区在鼠标拖拽选区到可视区域上下边缘时，会自动滚动并继续扩展选区，便于跨屏选取长文本
- 终端内容区优先保留原生文本选择能力，历史输出和持续输出中的已显示文本都可直接拖拽选中；因此不会把鼠标拖拽上报给启用鼠标协议的终端程序
- 终端内容区只会打开明确带有 `http`、`https` 或 `mailto` scheme 且格式完整的链接；普通选中文本、相对路径和不完整 URL 不会交给系统打开，避免 macOS 弹出“应用程序无法打开。-50”
- 终端内容区在用户滚动到历史输出后继续输入命令时，会自动回到最新输出位置，避免命令结果已写入底部但当前视口仍停留在历史区造成误判
- “复制调试”会同时带出密码存储访问日志和 SSH 密码自动填充事件，可用于判断远端密码提示后是否真的读取了 Keychain、以及密码是否实际写入了 SSH PTY
- ShellX 会识别“复制调试”生成的调试快照；粘贴回终端前会先提示确认，避免 `<ESC>` 等调试文本被误发送到交互程序
- 当前会话状态、主机地址与工作目录展示位于终端底部栏，减少顶部操作干扰
- 当前会话状态、主机地址、工作目录与会话标签展示位于终端底部栏，便于快速识别当前环境
- 终端底部栏的主机地址旁提供复制按钮，可一键复制当前连接地址到系统剪贴板
- 终端底部栏中的会话标签会根据浅色 / 深色主题自动调整前景、底色和描边对比度，避免标签在不同主题下发灰或难以辨认
- 全局配置中的“界面主题”支持跟随系统、浅色和深色三种模式，切换后会立即作用于当前应用窗口
- 全局配置中的“重新打开上次标签页”可控制关闭主窗口后再次打开时是否恢复关闭前仍在顶部标签栏中的终端标签；恢复多个标签时只会自动连接当前活动标签，其他标签会在切换到前台后再连接，避免重启后同时发起多条 SSH 连接被远端提前断开；关闭该选项后，关闭主窗口会同时结束当前终端连接，下次打开回到默认状态
- 全局配置中的“选中文本复制”可控制终端选区变化后是否自动复制到系统剪贴板；说明通过问号图标悬停提示展示
- 全局配置中的“终端历史行数上限”会立即作用于已打开标签，用于限制 scrollback 历史，降低长时间刷屏时的内存增长
- 全局配置中的“应用更新”会读取 `https://api.github.com/repos/dylan120/shellx/releases/latest`，将 Release `tag_name`（例如 `v0.2.0`）与当前应用版本比较；Release 需要附带 `.dmg` 或 `.zip` 安装资产以及同名 `.sha256` 校验文件，手动更新时会显示下载进度
- 开启“自动更新”后，ShellX 启动时会后台检查 GitHub Release；发现新版本后会自动下载，下载完成后在应用更新区域提示“立即重启”，由用户决定何时安装并重启生效
- 终端底部的普通状态提示会自动消失，也可通过提示旁的关闭按钮手动收起；只有连接失败等真实错误才会继续保留为错误信息，并提供“重连”“重新输入密码”和“复制错误”等恢复动作
- 支持 `lrzsz` 双向文件传输触发、多文件上传，以及在终端底部栏持续展示进度与速率
- 终端底部栏保留最近传输记录，可回看完成、失败或取消的 lrzsz / SFTP 传输结果
- lrzsz helper 会显式开启 verbose 输出，以便持续解析文件名、字节数、速率和 ETA
- lrzsz 上传在最后一个文件到达 100% 后会短延迟兜底收尾，避免部分远端 `rz` 已收完文件但本地 helper 退出回调迟到时底部进度一直停留在“上传中”
- lrzsz 下载在识别到远端 `sz` 结束帧后会短延迟兜底收尾，避免本地 `rz` 退出回调迟到时底部进度一直停留在“下载中”
- 当前已连接标签支持通过右击标签菜单发起 `SFTP 上传文件/文件夹`、`SFTP 下载文件` 和 `SFTP 下载文件夹`
- SFTP 传输进行中会在终端底部栏展示当前文件、百分比、已传输大小、速率和剩余时间（以远端 `sftp` 进度输出为准）
- 首次连接未知主机、主机指纹变更或服务器新增 host key 算法时都会展示指纹确认；私钥模式可启用 Keychain 集成；账号密码模式下会在远端真正提示密码时再尝试读取 Keychain 并自动回填
- 顶部菜单“脚本”提供“脚本管理”和“批量执行脚本”两个入口；脚本管理支持新增、编辑、删除和一键复制脚本内容，并可在 Shell / Python 语法之间切换高亮；脚本列表支持整行点击选择，右侧编辑区底部固定提供保存操作，保存已有脚本后会继续停留在该脚本，删除操作会优先作用于当前选中或右侧正在编辑的已有脚本
- 脚本管理的脚本内容区域支持打开大窗口查看和编辑，适合检查较长脚本；大窗口复用同一份草稿内容和语法高亮配置
- 批量执行脚本窗口复用全部会话树选择目标会话，支持为本次执行手动输入参数和超时时间，并在同一窗口展示每个会话的执行中、成功或失败状态；点击具体会话可查看该会话输出和 ShellX 诊断信息，也可终止选中主机或一键终止全部运行中的主机
- 批量脚本通过系统 `/usr/bin/ssh` 非交互执行到远端 `sh -s -- ...`，手动参数可在脚本中通过 `$1`、`$2`、`$@` 读取；执行前会校验目标主机已存在 ShellX `known_hosts` 信任记录；默认最多同时执行 6 个会话，单会话输出最多保留最后 128 KiB，默认超时 3600 秒，超时或手动终止后会结束对应 SSH 子进程
- 批量脚本失败时会在输出区追加 ShellX 诊断块，包含退出码或终止原因、会话、认证方式、远端命令、超时时间、SSH 参数摘要和常见排查方向；即使远端没有返回 stdout/stderr，也会展示可用于定位的失败上下文

## 已知限制

- 当前 `lrzsz` 依赖本机存在 `sz` / `rz` 命令，常见安装方式是 `brew install lrzsz`
- 当前版本已移除 `lrzsz` 传输时固定 `4 KiB` 缓冲限制，局域网场景会改用工具默认协商参数以避免异常低速
- 当前已增强 `tmux` / 包装 shell 命令下的方向识别与多文件上传；目录上传/下载仍建议优先使用右键菜单中的 SFTP
- 当前 SFTP 下载尚未提供远端文件树浏览，下载文件或文件夹时需要手动输入远端路径
- 当前本机终端默认优先使用 `/bin/zsh` 作为交互式非 login shell 启动；若目标机器不存在该路径，会自动退回用户环境中的 `SHELL` 或 `/bin/bash`
- 当前 `known_hosts` 由 ShellX 单独管理在 `Application Support/ShellX/known_hosts`，不会直接写入用户 `~/.ssh/known_hosts`
- 当前 host key 确认依赖 `ssh-keyscan` 预扫描结果；应用会显式尝试拉取 `ed25519/ecdsa/rsa` 多种 host key 算法。若目标端口在 SSH 握手阶段直接断开或网络环境限制扫描返回，未知主机会继续展示底层 `ssh-keyscan` 输出；已存在 ShellX `known_hosts` 记录的主机会在扫描失败时回退到 OpenSSH 严格校验，实际 SSH/SFTP 连接仍使用 `StrictHostKeyChecking=yes`
- 当前 SSH 会尝试通过 `SendEnv/SetEnv` 向远端发送 `LANG` / `LC_CTYPE`；若服务器禁用了 `AcceptEnv`，ShellX 只能保证本地 `ssh` 客户端保持 UTF-8，无法强制远端 shell 切换 locale
- 当前账号密码模式下，ShellX 会在远端真正提示密码时再尝试读取系统 Keychain 并自动回填；若读取不到，才会提示输入一次，并在开启保存到系统 Keychain 时重新写入
- 当前批量脚本执行仅支持 SSH Agent 和私钥认证会话；账号密码认证会话会在执行结果中直接标记失败，避免批量任务阻塞在交互式密码输入
- 当前批量脚本执行是非交互模式，不适合 `top`、`vim`、二次确认输入等需要 TTY 或持续交互的命令
- 远端网络出口仅作用于交互式 SSH 会话，不会自动改变 SFTP 传输和批量脚本执行的网络路径
- 远端网络出口依赖远端 SSH 服务允许 TCP 转发；如果服务端禁用了 `AllowTcpForwarding`、`PermitOpen` 或相关策略，连接会因为 `ExitOnForwardFailure=yes` 直接失败并显示 OpenSSH 错误
- 历史 `scripts.json` 中缺少脚本语言字段的记录会按 Shell 语法读取；保存脚本后会写入新的 `language` 字段
- 当前更新功能只接受 GitHub Release 中可通过 SHA256 校验的 `.dmg` 或 `.zip` 安装资产，并从中查找 `ShellX.app` 替换当前运行的 `.app`；不会执行 Release 包内自带脚本。若当前应用安装目录不可写，点击“立即重启”安装时会失败，需要手动安装下载的 Release 资产
- 当前自动更新只负责后台下载更新包，不会在下载完成后直接重启；用户点击“立即重启”后才会退出当前进程、替换 `.app` 并重新打开
- 若在会话编辑页启用了“将密码保存到系统 Keychain”并填写了新密码，保存时会立即创建或刷新 `com.shellx.session-password` 条目；若留空保存，则不会覆盖当前已保存密码
- 历史 `sessions.json` 中的 `notes` 字段会在读取时自动迁移为单个标签，并在下次保存后统一写回新的 `tags` 数组结构
- 单次 SSH 连接生命周期内，ShellX 只会尝试一次 Keychain 自动填充；若自动回填后远端仍再次提示密码，可通过“复制调试”查看是否已经真正把密码写入 SSH PTY
- 当前环境缺少 `swift` / `xcodebuild`，本次提交未执行本地编译和测试，只完成了工程与代码落地

## 生成 DMG 安装包

如果你希望生成的 `.dmg` 保留当前工程的签名身份（例如让 Keychain 尽量把 DMG 中的 `.app` 视为与 Xcode 运行版本相同的应用主体），可以直接使用仓库内脚本：

```bash
./scripts/build-electron-dmg.sh
```

默认输出：

- `dist/ShellX-Release.dmg`
- `dist/ShellX-Release.dmg.sha256`

常见选项：

```bash
./scripts/build-electron-dmg.sh --output-dir ./artifacts
./scripts/build-electron-dmg.sh --volume-name "ShellX Installer"
```

脚本依赖 `npm`、`hdiutil`、`codesign`、`xattr`、`shasum` 和 `/usr/libexec/PlistBuddy`。

## 发布 GitHub Release

```bash
./scripts/manual-release-electron-version.sh 1.2.0
```

脚本会更新 `electron-shellx/package.json` 和 `package-lock.json` 版本，运行 Electron 预检，构建 DMG，创建 `v<version>` tag，并通过 GitHub CLI 上传 `ShellX-Release.dmg` 与同名 SHA256。

常见选项：

```bash
./scripts/manual-release-electron-version.sh 1.2.0 --yes
./scripts/manual-release-electron-version.sh 1.2.0 --skip-tests
./scripts/manual-release-electron-version.sh 1.2.0 --notes "Release notes"
```

## 本地安装与 Gatekeeper

本地未公证构建如果提示“ShellX.app 已损坏，无法打开”，通常是 ad-hoc 签名或隔离属性导致。可先拖到 `/Applications`，再执行：

```bash
sudo codesign --force --deep --sign - /Applications/ShellX.app
sudo xattr -dr com.apple.quarantine /Applications/ShellX.app
open /Applications/ShellX.app
```

如果仍失败，可兜底清理所有扩展属性：

```bash
sudo xattr -cr /Applications/ShellX.app
open /Applications/ShellX.app
```

正式分发仍建议补充 Developer ID 签名和 notarization。

## 已知限制

- 当前 Electron 打包脚本默认生成本机架构目录包；跨架构分发需要补充通用架构/多架构发布策略。
- SFTP 下载仍需要手动输入远端路径，尚未提供远端文件树浏览。
- lrzsz 依赖本机存在 `rz` / `sz` 命令，常见安装方式是 `brew install lrzsz`。
- 批量脚本执行仅适合非交互命令，不适合 `top`、`vim` 或需要二次确认的任务。
- 远端网络出口依赖远端 SSH 服务允许 TCP 转发；如果服务端禁用了 `AllowTcpForwarding` 或相关策略，连接会失败。
- 如果服务器 sshd 禁止 `AcceptEnv`，ShellX 只能保证本地 ssh 客户端为 UTF-8，不能强制远端登录 shell 切换 locale。

## 兼容性说明

- 当前 Electron 数据目录为 macOS `Application Support/ShellX-Electron`。
- 首次启动会尝试从旧 ShellX 应用支持目录迁移会话、脚本和 `known_hosts`，并写入迁移标记避免重复导入。
- 账号密码不写入会话文件；若启用 Keychain 保存，会话连接时在远端真正提示密码后读取并回填。
- Release tag 使用 `v<version>`，应用版本来自 `electron-shellx/package.json`。
